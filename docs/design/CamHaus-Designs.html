CamHaus design specs

The rules the playground follows. Numbers tied to the inspector update as you change it.

Geometry

Measured from NSScreen at runtime, snapped to device pixels, recomputed when displays or scaling change.

let left  = screen.auxiliaryTopLeftArea!   // visible strip left of the housing
let right = screen.auxiliaryTopRightArea!  // visible strip right of it
let h     = screen.safeAreaInsets.top
let notch = NSRect(x: left.maxX, y: screen.frame.maxY - h,
                   width: right.minX - left.maxX, height: h)
  • Nothing is drawn inside the camera housing: it has no pixels. Every open layout leaves a gap exactly the housing's width in its top row.
  • Closed, CamHaus matches the housing: pure black (#000000), concave ears where it meets the top edge, rounded bottom corners.
  • The housing's size in points changes with display scaling, and developers have measured different heights on different models. Never hard-code it.
  • Every edge lands on a device pixel. At rest, widths and heights are whole numbers of pixels.
  • Open, the panel background is the same pure black as the housing — never a tint, material or wallpaper bleed. Content sits on subtle elevated fills.

Motion

A small set of springs, all interruptible. Content follows the shape, never the other way round.

  • Open grows the black shape, then fades content in with a short blur-to-sharp. Close fades content first, then shrinks.
  • With Reduce Motion on, size changes are instant and content cross-fades in 150 ms.
  • Hover waits for intent (the hover delay), so a pointer flicking past doesn't open anything.

Type

System font through macOS text styles. Inside the notch, nothing smaller than 10 pt.

Color

The notch is always dark, so its content uses the dark variants of the system colors in both appearances.

Components

Battery rings follow Apple's battery colors. Live activities keep content out of the housing.

  • Green above 20%, red at 20% or below, a bolt while charging.
  • The earbuds show one number when they're within 5% of each other, otherwise L and R separately.

Getting a screenshot into Claude Code

Four routes, each with a real failure mode. Switch between them in the inspector.

RouteHow it worksCatch
HookCamHaus installs a UserPromptSubmit hook that returns hookSpecificOutput.additionalContext naming the file, so the next thing you type carries the screenshot with it.Fires on your next message, not the moment you capture. Reported to be dropped in the VS Code extension; the CLI is fine.
MCPCamHaus runs a small MCP server with a latest_screenshot tool that returns an image content block. Whichever session is live pulls it.The sturdiest of the four, but the session has to ask. Some clients show the image to the model and not to you.
ClipboardThe image goes on the pasteboard; you press ⌃V in the prompt.Native on macOS, but paste is known to fail silently now and then.
ManualThe tray sits there. Drag it anywhere, or press Send.Nothing automatic. The one that always works.
  • Typing into someone else's terminal is deliberately not on the list: it needs Accessibility, breaks on every terminal but the one you tested, and can't tell which pane holds the live session.
  • The tray appears where you captured. macOS shows its own thumbnail bottom right, so turn that one off in Screenshot's Options or you get two.
  • Routing never moves the original. Every screenshot is in the stash whichever route is on.

Keyboard

Standard Mac keys inside the notch. Global shortcuts always use a modifier and can be changed.

Claude in the notch

Live sessions plus the three numbers that matter: context, the 5-hour session, and the weekly limits.

StatSourceFields
Context usedStatusline JSONClaude Code pushes JSON to a configured statusline command: context_window.used_percentage, total_input_tokens, context_window_size, plus model.display_name and cost.*.
Session (5 h), Weekly, Fable weeklyGET /api/oauth/usageOn api.anthropic.com, bearer token from ~/.claude/.credentials.json. The limits[] entries carry kind, percent, resets_at; model-scoped entries name the model — that row is the Fable gauge.
Sessions and phasesClaude Code hooksSessionStart/Stop, tool and permission events over a local socket, with the transcript JSONL for history — Nook's approach, reimplemented fresh.
Screenshots into a sessionTerminal input injectionThere is no public API for injecting into a running interactive session, but Claude Code reads image paths typed into the prompt (drag-and-drop into the terminal inserts a path, and ⌃V pastes an image). “Send to Claude” therefore targets the session's terminal — tmux send-keys when the session runs in tmux (the hook event carries the pane), otherwise focus the terminal app and paste via scripting — and inserts the stack's file paths in order.
  • Sources: Claude Code statusline docs (official field list); ccusage (PyPI) and claude-limitline, which document the usage endpoint and its auth; Nook (GPL-3.0 — the sessions-in-the-notch idea, hook architecture and tmux terminal routing, no code reused).
  • The glyph is the official Claude Code pixel mark, path taken verbatim from LobeHub's icon set (@lobehub/icons-static-svg, MIT packaging; the logo itself is Anthropic's, shown here to represent Anthropic's own tool) in the brand terracotta #D97757. No animated version is published anywhere, so the walk-and-blink while a session is working is CamHaus's own, built by splitting the mark into body, eye and leg layers; it freezes under Reduce Motion.
  • The usage endpoint is Claude Code's own, not a public API: poll gently (on open, then every few minutes), expect it to change, and hide the card rather than show stale numbers.
  • Phases: working (green, pulsing), needs you (orange — also surfaces in the closed notch), idle (gray). A waiting session is the only thing allowed to keep a live activity up indefinitely.
